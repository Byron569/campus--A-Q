## 1. 方法说明（Scrum 适配到「单人 + AI」）

原方案是标准 Scrum，但本项目只有客户一人 + AI，部分仪式需要换算，不能照搬。

| Scrum 标准 | 本项目形态 | 说明 |
| --- | --- | --- |
| Product Backlog | `docs/03` 任务清单 + 本文档 §3 | 33 个任务，已带点数与依赖 |
| Sprint（固定周期） | **不设固定周期，按里程碑收口**（客户裁决） | 结束条件 = 完成标准全部通过，**不是**到了某一天 |
| Sprint Planning | 每个 Sprint 开头由客户确认目标 | 已在需求/设计阶段完成拆解 |
| Daily Standup | **每完成一个功能块同步一次**（客户裁决） | 保留站会核心职能：暴露阻塞 |
| Sprint Review | 每个 Sprint 结束提交客户验收 | 已验证通过才进下一个 |
| Sprint Retrospective | 每个 Sprint 结束我出一份回顾 | 记录做对了什么、下次改什么 |
| Code Review | **AI 自审 + 客户抽查**（客户裁决） | 自审清单模板见 §6 |
| 联调 | **模块间联调**，非前后端联调 | 见 §7 |

**本项目的「联调」不是前后端对接**：Streamlit 服务端渲染，页面与逻辑同进程，不存在两边各写接口再对接。真实风险在模块之间的缝——检索口径、进度计数、权限过滤、级联删除。

## 4. Definition of Done（每个任务完成的定义）

一个任务只有在**全部满足**以下几点时才算完成，缺一不可：

1. **代码写完**，符合 `docs/02` §3 的目录结构与 §10 配置项清单。
2. **自测通过**：能手动跑一次并看到预期结果（开发自测）。
3. **单元测试**：该任务若在 `docs/03` §6.1 有对应用例，测试必须通过；否则需说明为何无需测试。
4. **`pytest` 全绿**：不得引入回归。
5. **异常路径覆盖**：按 `docs/02` §11 异常处理策略表，该任务的异常分支已实现且有明确文案。
6. **无敏感信息入库**：`.env`、`data/`、`backups/`、`.idea/` 未被提交。
7. **提交信息规范**：Conventional Commits（`feat` / `fix` / `docs` / `refactor` / `test` / `chore`）。
8. **自审清单已出**：见 §6。

## 5. 进度同步格式（替代每日站会）

每完成一个功能块，我按固定格式同步，**不写废话**：

```
【功能块】FB-1.x 名称
【状态】完成 / 部分完成 / 阻塞
【做了什么】一句话 + 关键文件
【验证】怎么验的、看到什么结果
【阻塞或风险】有就写，没有写「无」
【下一步】下一个功能块
【自审清单】见 §6 模板
```

**阻塞上报规则**：同一个问题连续两次无法推进，**立即停下汇报**，不自行绕过、不降低标准、不伪造通过结果。

## 7. 联调策略（模块间联调矩阵）

没有前后端联调，取而代之的是**跨模块缝的联调矩阵**。每个 Sprint 结束前逐行验证：

| 缝 | 涉及模块 | 要验证什么 | Sprint |
| --- | --- | --- | --- |
| C-01 | `ingest.splitter` ↔ `ingest.pipeline` ↔ `chroma.add_chunks` | 切片数 = 写入条数 = `documents.chunk_count`；元数据字段齐全 | S1 |
| C-02 | `ingest.tasks` ↔ `repository` ↔ 前端进度 | 进度计数不跳变、不回退；失败有 error | S1 |
| C-03 | `chroma.delete_by_doc_id` ↔ `repository.soft_delete` ↔ 文件系统 | 删除后三处一致，检索无残留 | S1 |
| C-04 | `providers.embedding` ↔ `chroma` | 集合 `hnsw:space=cosine`；相似度 = 1 − 距离；维度一致 | S1 |
| C-05 | `rag.retriever` ↔ `chroma.search` | 阈值只作用于向量路；`matched_by` 正确；分类过滤生效 | S2 |
| C-06 | `rag.chain` ↔ `retriever` ↔ `repository` | 拒答不调 LLM；降级能出原文；引用落库与展示一致 | S2 |
| C-07 | `auth.service` ↔ UI 守卫 ↔ `repository` | 访客拦截、禁用账号、角色权限三处一致 | S3 |
| C-08 | **`VectorStore.search` 的 user_id** ↔ 所有调用方 | **每一处调用都传了 user_id；缺传即抛错**（安全红线） | S3 |
| C-09 | `repository.delete_user` ↔ `chroma.delete_by_user_id` ↔ 文件系统 | 注销后三处无残留 | S3 |

> C-08 是安全红线专项，必须在 Sprint 3 用测试用例固定住。

## 11. Sprint 回顾

### Sprint 1（M1 数据底座）

**做对了什么**

1. **纯逻辑与 Streamlit 渲染分离**：校验 / 落盘 / 级联删除 / 重试都是不依赖 `st.*` 的纯函数，能用单元测试覆盖；渲染层用浏览器读 `getComputedStyle` 实测。两个层次各自可验证。
2. **关键约束用测试钉死**：集合距离度量必须为 cosine（C-04）、进度写入序列必须单调（C-02）、漏传 `user_id` 必须抛错（FR-31 安全红线）、上传上限必须比业务上限宽（DR-03）。这几条都是"改坏了不会立刻报错、但语义已错"的地方。
3. **主动用真实资料反证假设**：客户上传的《编译原理》实验教程直接暴露了「中文字符间空格」与「合并单元格重复」两个样例数据覆盖不到的数据质量缺陷。

**哪里返工**

| 问题 | 怎么发现的 | 责任归类 |
| --- | --- | --- |
| 切片器 `keep_separator` 取值反了，切片在断句处收尾而不是句号 | 单元测试 | 实现错误 |
| 相似度阈值 0.35 完全不起过滤作用 | 样例数据实测 → CR-02 变更 | 设计参数未经校准 |
| DR-07 幂等校验写在自己刚建的任务之后，入库线程从未启动 | 浏览器实测 | **实现错误（单测与 CLI 都测不出）** |
| 提交结果被随后的 `st.rerun()` 冲掉、进度轮询无上限会挂住页面 | 浏览器实测 | 同上 |
| 中文字符间空格、DOCX 合并单元格重复抽取 | 真实资料实测 → docs/02 v1.5 | 设计未覆盖 |
| 验证过程中误删了客户的真实资料（已从 `~/Downloads` 恢复） | 客户反馈 | **验证流程缺陷** |

**下个 Sprint 要改什么**

1. **凡涉及 UI 的功能块，代码写完必须先在浏览器里跑通主流程再报完成**。「DR-07 校验位置错误」和「提交结果被冲掉」两个问题都属于"代码逻辑自洽、界面行为不对"，单元测试和命令行自测都发现不了。
2. **破坏性验证要先声明边界**：用浏览器自动化验证时，明确禁止触碰删除类按钮；不在含真实数据的库上做破坏性验证，改在隔离的 `DATA_DIR` 里跑。
3. **数据质量靠真实资料驱动**：样例数据会掩盖问题。真实资料到位后应立即重跑入库并检查切片文字质量。
