## 1. 引言

### 1.1 编写目的

明确一期「校园知识库问答」系统的功能与非功能需求，作为设计、开发、测试与验收的唯一依据。

### 1.2 项目背景

校园资料分散在通知、学生手册、课件中，格式杂乱、查找困难；通用大模型又容易编造学校政策，学生无法核验。本项目建立**带引用溯源的 RAG 知识库问答系统**，让答案可追溯到原文。

### 1.3 术语与缩写

| 术语 | 含义 |
| --- | --- |
| RAG | 检索增强生成。先检索资料，再让模型基于资料作答 |
| Chunk | 文档切片，检索的最小单位 |
| Embedding | 向量化，把文本转成向量用于相似度计算 |
| BM25 | 关键词检索算法，擅长精确词命中 |
| 混合检索 | 向量检索与 BM25 同时召回再融合排序 |
| Query 改写 | 把多轮追问改写成独立完整的问题再检索 |
| Top-K | 检索返回的最相关切片条数，默认 5 |
| 相似度阈值 | 低于该分数的切片丢弃，默认 0.6（CR-02 由 0.35 上调） |
| 引用溯源 | 答案标注来源文档与原文片段，供核验 |
| 幻觉 | 模型编造事实；本项目通过强制引用与拒答抑制 |
| 拒答 | 知识库无相关内容时，回答固定文案「知识库中暂无相关资料，建议咨询学生工作处」 |
| 降级 | LLM 不可用时退化为只展示检索到的原文片段 |
| 公共文档 | 管理员导入、全员可见的校园资料（`is_public=1`） |
| 个人资料 | 用户自己上传、仅本人可见的资料（`user_id=本人`） |
| 未分类 | 用户上传个人资料时未指定分类的归属（`category=uncategorized`） |
| 异步入库 | 上传后后台处理，页面轮询进度，不阻塞用户 |
| 配置驱动 | 学校信息、分类、模型供应商由配置文件定义 |

### 1.4 参考资料

- `.trae/documents/campus-rag-development-plan.md`（决策过程与总体背景）
- `docs/02-架构设计.md`
- `docs/03-开发任务清单.md`

## 2. 项目概述

### 2.1 产品定位

面向大学生的校园助手，核心是**带引用溯源的 RAG 知识库问答**，不是通用大模型套壳。产品名「校答」，仓库名 `campus-qa`。

### 2.2 目标用户与干系人

| 干系人 | 说明 | 关注点 |
| --- | --- | --- |
| 新生 | 首次入学，对流程完全陌生 | 报到、宿舍、军训、校园卡怎么办 |
| 在校生 | 事务与学业并行 | 请假、奖学金、补考、图书馆规则 |
| 管理员 | 系统维护者（本项目由开发者担任） | 导入公共文档、管理用户、看使用情况 |
| 访客 | 未登录用户 | 一期**不可用**，只能看到登录页 |

### 2.3 业务目标

1. 让学生用一个入口查到校园事务的准确答案，并能核验原文。
2. 系统不得编造学校政策；无资料时必须明确拒答。
3. 换一所学校时，只修改配置文件与资料，不改代码。

### 2.4 约束与假设

| 编号 | 类型 | 内容 |
| --- | --- | --- |
| CON-01 | 约束 | 大模型走云端 API，不本地部署模型 |
| CON-02 | 约束 | 开发机为 macOS（Apple M1 / arm64 / 16GB），另需兼容 Windows 64 位（x64） |
| CON-03 | 约束 | 服务以局域网方式提供，手机与其他电脑用浏览器访问 |
| CON-04 | 约束 | 一期不引入 Docker、云服务器、消息队列等重型组件 |
| ASM-01 | 假设 | 入库资料以可复制文字的 PDF/DOCX/TXT/MD 为主；若大量为扫描件，需提前启用 OCR |
| ASM-02 | 假设 | 一期并发不超过 20 人 |
| ASM-03 | 假设 | API Key 由管理员统一配置，成本由管理员承担 |
| ASM-04 | 假设 | 用户名几乎不限制字符，用户会自觉使用便于识别的名称 |

### 3.2 P0 需求详细描述

#### FR-01 用户注册

- **输入**：用户名、密码、确认密码、协议勾选
- **处理**：校验 → 唯一性检查 → pbkdf2 加盐哈希 → 落库 → 自动登录
- **输出**：注册成功，进入问答页
- **异常**：用户名已存在 / 密码不足 6 位 / 两次密码不一致 / 未勾选协议 —— 均需明确提示，且不清空已填内容
- **验收要点**：数据库仅存哈希不存明文；四种异常均有独立提示文案

#### FR-02 用户登录 / 登出

- **输入**：用户名、密码
- **处理**：查用户 → 校验状态是否为 `disabled` → 校验密码哈希 → 写登录态
- **输出**：登录成功进入问答页；登出清空登录态回到登录页
- **异常**：用户名或密码错误（统一提示，不暴露哪个错）/ 账号被禁用 / 账号不存在
- **验收要点**：被禁用账号即使密码正确也无法登录

#### FR-03 角色权限

- **输入**：当前登录用户的 `role`
- **处理**：`app.py` 做页面守卫；管理员页仅 `admin` 可进
- **输出**：`user` 看不到管理员页入口
- **异常**：直接构造 URL 访问管理员页 → 拦截并跳回问答页
- **验收要点**：`user` 无论何种方式都无法进入管理员页

#### FR-04 访客拦截

- **输入**：任意页面访问
- **处理**：检查登录态，无则渲染登录页
- **输出**：未登录用户只能看到登录 / 注册界面
- **异常**：无
- **验收要点**：未登录状态下无法通过任何入口发起检索或上传

#### FR-05 文档上传

- **输入**：一个或多个文件（PDF / DOCX / TXT / MD）、分类（可选）、可见性（普通用户固定为个人）
- **处理**：逐个校验类型与大小 → 文件名清洗 → 落盘到 `data/uploads/<user_id>/` → 写 `documents` 记录 → 为每个文件建入库任务
- **输出**：上传成功提示，列表中出现对应记录与任务进度
- **异常**：类型不支持 / 超过大小上限 / 文件为空 / 文件名含非法字符 —— 逐个文件独立报错，不影响同批其他文件
- **验收要点**：一次选 3 个文件（其中 1 个超限），其余 2 个正常入库，超限的那个有明确提示

#### FR-06 异步入库

- **输入**：入库任务
- **处理**：后台线程执行解析 → 切片 → 分批向量化，按批更新 `done_chunks`
- **输出**：进度条实时推进；完成显示成功；失败标红并展示原因
- **异常**：解析失败 / 向量化失败 / 进程中断 —— 记录 `error`，状态置 `failed`，提供「重试」按钮（不自动重试）
- **验收要点**：失败任务可通过重试按钮重新入库并成功

#### FR-07 文本预处理

- **输入**：解析出的原始文本
- **处理**：清洗（去多余空行与行首尾空白）→ 结构切分（标题/空行）→ 超长块递归切分
- **输出**：带元数据的切片列表
- **异常**：文本为空或全为空白 → 任务标记失败并提示「未能从文件中提取到文本」
- **验收要点**：标题与其后正文不被切散；短段落完整保留

#### FR-08 知识库问答

- **输入**：问题文本、当前会话历史、可选分类限定
- **处理**：Query 改写 → 混合检索（权限过滤）→ 组装上下文 → LLM 流式生成 → 解析 `【来源N】`
- **输出**：流式输出的答案 + 引用卡片 + 反馈按钮
- **异常**：LLM 异常走 FR-21 降级；检索无结果走 FR-10 拒答
- **验收要点**：答案能从来源卡片核对到原文

#### FR-09 引用溯源

- **输入**：本次检索命中的切片
- **处理**：按相似度排序，取 Top-K 作为来源，写入 `message_sources`
- **输出**：每条来源显示文档名 + 原文片段 + 相似度分数，可展开查看
- **异常**：无
- **验收要点**：答案中的 `【来源N】` 与来源卡片一一对应

#### FR-10 无资料拒答

- **输入**：检索结果为空，或全部低于相似度阈值
- **处理**：**不调用 LLM**，直接返回固定文案
- **输出**：`知识库中暂无相关资料，建议咨询学生工作处。`
- **异常**：无
- **验收要点**：问知识库外的问题，输出与固定文案完全一致，且不附带任何检索结果

#### FR-11 多轮对话

- **输入**：当前问题 + 最近 N 轮（默认 5）历史
- **处理**：把历史与当前追问交给 LLM 改写成独立问题 → 用改写结果检索
- **输出**：保持上下文连贯的答案
- **异常**：改写失败 / 历史为空 / 改写结果为空 → 退化为原问题直接检索
- **验收要点**：先问「搬宿舍流程」，再问「提前几天」，能召回搬宿舍相关资料

#### FR-13 文档管理

- **输入**：列表查询（分页）、删除操作
- **处理**：分页查询本人文档（管理员可查公共文档）；删除时置 `status=deleted` → 删向量 → 删原始文件
- **输出**：分页列表（文件名、分类、状态、切片数、时间）；删除后列表更新
- **异常**：删除时向量清理失败 → 记录错误但保留文档记录，提示用户重试
- **验收要点**：删除后检索不到该文档任何内容

#### FR-15 公共文档管理

- **输入**：管理员上传 / 删除公共文档
- **处理**：上传时 `is_public=1`、`user_id=NULL`；删除同 FR-13
- **输出**：公共文档进入全库可检索范围
- **异常**：同 FR-05
- **验收要点**：普通用户能看到并检索到管理员上传的公共文档，但不能删除

#### FR-25 用户注销

- **输入**：注销请求 + 二次确认
- **处理**：删除该用户全部 `documents`（含原始文件与对应向量）→ 删除 `conversations` / `messages` / `feedback` / `ingest_tasks` → 删除用户记录
- **输出**：注销成功，退出登录回到登录页
- **异常**：删除过程中断 → 中止并回滚，提示「注销失败，请重试」，不留下半删状态
- **验收要点**：注销后用该用户名无法登录；管理员侧查不到该用户任何文档、会话、反馈；检索无残留

#### FR-27 配置驱动

- **输入**：`config/knowledge_base.yaml`、`.env`
- **处理**：启动时读取；学校信息与分类用于界面展示与分类过滤；模型与路径用于初始化 Provider
- **输出**：界面显示配置中的学校名与联系方式；分类下拉来自配置
- **异常**：配置文件缺失或格式错误 → 启动时明确报错并给出示例
- **验收要点**：改 yaml 里的学校名与分类后重启，界面与分类选项随之变化，代码零改动

#### FR-28 用户协议与隐私说明

- **输入**：注册时的勾选动作
- **处理**：展示协议内容（含数据会发送给 LLM API、日志记录范围、日志 90 天保留、可注销删除）
- **输出**：未勾选则注册按钮不可用
- **异常**：无
- **验收要点**：不勾选无法完成注册

#### FR-31 数据隔离与权限过滤（安全红线）

- **输入**：检索请求（query + 当前用户身份 + 可选分类）
- **处理**：检索入口统一封装，**强制**注入过滤条件 `is_public = 1 OR user_id = 当前用户`；公共文档在元数据中 `user_id = -1`、`is_public = 1`；个人资料 `user_id = 本人`、`is_public = 0`
- **输出**：只返回当前用户有权查看的切片
- **异常**：过滤条件缺失 → 视为代码缺陷，**直接抛错并不返回任何数据**（宁可报错，不可越权下发）
- **验收要点**：用户 A 用任意问法、任意分类、任意时点检索，均无法命中 B 的个人资料；双方都能命中公共文档
- **实现约束**：所有向量查询必须经由 `VectorStore.search()`，禁止上层直接调用 Chroma；由 TC-U16 专项覆盖

#### FR-23 日志清理

- **输入**：系统启动时 / 定时触发
- **处理**：删除 `qa_metrics` 中 `created_at` 早于 90 天的记录
- **输出**：清理条数记入日志
- **异常**：清理失败不影响主流程，记录 WARN 下次重试
- **验收要点**：构造 91 天前的记录，触发清理后该记录不存在
- **说明**：本需求为 **P0**，因为《用户协议》中已对外承诺「日志保留 90 天」，属承诺兑现项，不可延后

## 9. 验收标准

一期验收以以下 12 条为准（全部通过即验收通过）：

1. 注册登录后可批量上传多个文档（含 DOCX），异步入库有进度，完成后能提问并标注来源与相似度分数。
2. 追问（如「提前几天申请？」）能正确改写并召回正确资料。
3. 知识库外的问题，输出固定拒答文案且不附带检索结果。
4. 用户 A 检索不到 B 的个人资料；双方都能检索到公共校园文档。
5. 手动限定「只搜新生事务」后，召回结果限定在该分类。
6. 断开网络 / API Key 失效时，系统降级展示检索到的原文片段，页面不崩溃。
7. 手机与 Windows 同局域网浏览器可正常访问并完成一次上传与提问。
8. 更换配置文件的学校信息与分类后，不改代码即可适配另一批资料。
9. 评测集输出准确率、引用命中率、拒答正确率、追问改写成功率四个数字。
10. 用户注销后，其个人文档、向量、会话与反馈被彻底清理，检索无残留。
11. 管理员能查看用户列表、禁用 / 删除用户。
12. 入库失败的任务可通过「重试」按钮成功重新入库。

### 10.3 需求冲突与取舍

| 冲突 | 双方 | 取舍 | 代价 |
| --- | --- | --- | --- |

## 11. 需求优先级（MoSCoW）

### 11.1 判定标准

| 级别 | 判定标准 |
| --- | --- |
| **Must** | 缺失则一期无法交付、无法演示或无法通过验收 |
| **Should** | 重要且应在一期交付，但即便延后也不影响核心链路跑通 |
| **Could** | 锦上添花，做了加分，不做不影响任何验收项 |
| **Won't** | 本期明确不做，已记录在案，避免反复讨论 |

**工作量**为相对复杂度点数（1/2/3/5/8），**不是时间估算**，仅用于校验优先级分布是否健康。
**稳定性**：稳定 = 需求清晰不易变；易变 = 依赖后续反馈可能调整。

| FR-02 | 登录 / 登出 | 2 | FR-01 | 稳定 | 访客拦截与数据隔离的前提 |
| FR-03 | 角色权限 | 1 | FR-02 | 稳定 | 公共文档与用户管理的前提 |

## 12. 变更管理

1. **提出**：任何变更先记录，写明「变更点 / 原因 / 影响范围（FR、NFR、表结构、里程碑）」。
2. **评估**：评估是否影响已完成里程碑、是否改表结构、是否影响验收标准。
3. **决策**：客户确认接受 / 拒绝 / 延后。
4. **落库**：接受的变更写入本文档并同步更新受影响的 FR/NFR 与验收标准。
5. **冻结**：每个里程碑开发期间需求冻结，新想法记入「待评估变更」，下个里程碑开头处理。
