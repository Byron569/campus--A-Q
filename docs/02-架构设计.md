### 1.2 架构原则

| 原则 | 落地方式 |
| --- | --- |
| 配置驱动 | 学校信息与分类在 `config/knowledge_base.yaml`；模型与路径在 `.env` |
| 供应商无关 | LLM / Embedding 统一接口，换供应商只改配置 |
| 权限内聚 | 向量检索入口统一封装，强制传 `user_id`，杜绝越权 |
| 失败可降级 | 检索不依赖 LLM，LLM 挂了仍可用 |
| 可追溯 | 所有切片带元数据，答案可回溯到原文片段 |

## 2. 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 语言 | Python 3.12 | 本机环境已就绪；生态最全 |
| RAG 框架 | LangChain | 生态成熟，Agent / 工具调用文档最全 |
| 前端 | Streamlit | 纯 Python 出网页 UI，开发最快 |
| 向量库 | Chroma | 本地持久化、零运维、支持元数据过滤 |
| 关系库 | SQLite | 单机部署够用，WAL 后可支撑 20 并发读多写少 |
| LLM | 云端 API（默认 DeepSeek） | 不占本地算力；OpenAI 兼容协议统一接入 |
| Embedding | 本地 `BAAI/bge-small-zh-v1.5` | 免费、无调用成本、向量不出本机 |
| 文档解析 | pypdf + python-docx | 覆盖 PDF 与 DOCX 文本抽取，依赖轻 |
| 关键词检索 | rank_bm25 + jieba | 补齐中文专有名词召回短板 |
| 密码哈希 | hashlib.pbkdf2_hmac | 标准库实现，零额外依赖 |
| 测试 | pytest | 标准选择 |

**备选与取舍**

- 不选 LlamaIndex：Agent 与工具调用生态不如 LangChain 完善。
- 不选 Qdrant：需要额外服务进程，Chroma 内嵌足够。
- 不引入 Celery / Redis：异步入库用后台线程即可，避免重型依赖。

## 4. 关键模块设计

### 4.1 Provider 抽象层

统一走 OpenAI 兼容协议，用 `base_url` 切换供应商。

`config/settings.py` 关键配置项：`LLM_PROVIDER`、`LLM_MODEL`、`LLM_API_KEY`、`LLM_BASE_URL`、`EMBEDDING_PROVIDER`、`EMBEDDING_MODEL`、`RETRIEVE_TOP_K`、`RETRIEVE_SCORE_THRESHOLD`、`VECTOR_WEIGHT`、`BM25_WEIGHT`、`HISTORY_ROUNDS`、`HOST`、`PORT`、`MAX_UPLOAD_MB`、`PAGE_SIZE`。

供应商注册表：

| provider | base_url | 默认模型 |
| --- | --- | --- |
| deepseek（默认） | `https://api.deepseek.com/v1` | deepseek-chat |
| dashscope | `https://dashscope.aliyuncs.com/compatible-mode/v1` | qwen-max |
| zhipu | `https://open.bigmodel.cn/api/paas/v4` | glm-4-plus |
| openai | `https://api.openai.com/v1` | gpt-4o |
| custom | 由 `LLM_BASE_URL` 提供 | 由 `LLM_MODEL` 提供 |

Embedding 工厂：`local` → `HuggingFaceEmbeddings(bge-small-zh-v1.5, normalize_embeddings=True)`；`cloud` → `OpenAIEmbeddings(...)`。两者返回同一接口，上层无感知。

**启动预热**（DR-10）：服务启动后**异步加载一次本地 embedding 模型**并编码一条测试文本。本地 BGE 首次加载需数秒，若不预热，第一个提问的用户会被模型加载阻塞。预热失败只记 WARN，不影响启动。

### 4.2 文档接入与切片

**解析**：PDF 用 `pypdf` 逐页抽取；DOCX 用 `python-docx` 抽取段落文本（**表格一并抽取，同一行内重复的合并单元格去重**，否则横向合并会让一个值被刷成 `值 | 值 | 值`）；TXT/MD 直接读取。

**DOCX 表格的位置**（v1.9 修正）：段落与表格必须**按文档正文的先后顺序**混排抽取。python-docx 把 `paragraphs` 与 `tables` 拆成两个列表，若按「先全部段落、再全部表格」拼接，表格会被整体搬到文末、粘到最后一节，标题（如「二、审批权限」）下空无一物——检索命中标题却取不到表格内容，模型只能拒答。

**清洗**（v1.5 补充）：去多余空行、去行首尾空白、**去掉中文字符之间的空白**。中文本就不用空格分词，而 Word 的分散对齐与 PDF 转换常在中文字符间塞入半角空格或全角空格（`U+0020` / `U+3000`），留着会破坏 BM25 的 jieba 分词召回。清理只针对「两侧都是中日韩字符或中文标点」的空白，英文、数字之间以及中英之间的空格（如 `Python 语言`、`第 3 章`）一律保留。

**图片型 PDF 检测**：若「平均每页可提取字符数」低于阈值（默认 20），标记 `needs_ocr=True` 并在入库结果中回传警告。这是 OCR 风险的前置探测器。

**中文两阶段切片**：

1. 结构切分：按标题（`第X章`、`一、`、`（一）`、`1.`、Markdown `#`）与空行段落切成语义块；标题与其后正文保持同块。
   - `1.` 形式的数字编号要分两种身份：**单行**的数字段落算标题（「3. 校园卡办理」），**同段内连续多行**的算列表项（「1. 录取通知书原件」）。若把列表项当标题，标题会与紧随其后的清单被拆成两块，检索命中标题切片却取不到内容（v1.9 修正）。
2. 递归兜底：超长块用 `RecursiveCharacterTextSplitter`，分隔符优先级 `["\n\n", "\n", "。", "；", "，"]`，`chunk_size=500`、`chunk_overlap=80`。

每个切片携带元数据：`doc_id / user_id / is_public / category / filename / chunk_index / source_type`。

### 4.3 混合检索

```
query
 ├─ 向量路：Chroma.similarity_search_with_score
 │           where = (is_public=1 OR user_id=me) [AND category=xxx]
 │           相似度 = 1 - 余弦距离（集合按 cosine 建，量纲 0~1）
 │           ▶ 阈值过滤在此路生效：相似度 < 0.6 丢弃（DR-01，值见 CR-02）
 │
 └─ 关键词路：BM25（jieba 分词）
             ▶ 不使用相似度阈值：BM25 分数无上界、量纲不同，套向量路的阈值会错
             ▶ 命中判定只用「内容词元」（长度 ≥ 2、非停用词、含字母/数字/汉字）；
               虚词与标点不算命中，否则任意问题都会命中大文档（v1.8）
        ↓
 EnsembleRetriever 融合（向量 0.6 / BM25 0.4）
        ↓
 Top-K（默认 5）
```

**关键点**

1. Chroma 集合创建时指定 `hnsw:space = cosine`；Embedding 向量已归一化，因此「1 - 距离」即为余弦相似度，阈值语义直观。
2. **阈值只作用于向量路**（DR-01 裁决）。两路量纲不同：向量相似度是 0~1 的余弦值，BM25 是无上界的关键词分，混用同一阈值会导致 BM25 结果被错误过滤或全量放过。
3. **「命中」的判定规则**（决定是否触发拒答，FR-10）：

```
命中 = (向量路存在相似度 ≥ RETRIEVE_SCORE_THRESHOLD 的切片)
      OR (BM25 路存在内容词元命中的切片)

未命中 → 不调用 LLM，直接输出固定拒答文案
```

   即：只要有一路给出有效候选，就算命中并进入生成；两路都空才拒答。这样既避免了「向量分低但关键词精准命中」被误杀，也保证了「两路皆空」时必定拒答。

### 4.4 多轮对话与 Query 改写

- 会话与消息落 SQLite，刷新不丢，可多开切换。
- **「当前会话 id」存 `st.session_state`**（DR-08）。落库的是消息，当前选中哪个会话属会话态，不入库。
- 每轮先把「最近 N 轮（默认 5）历史 + 当前追问」交给 LLM 改写为独立问题，再检索。
- 改写失败、历史为空、或改写结果为空 → 退化为原问题直接检索。

### 4.5 生成与防幻觉

系统提示词硬约束：

1. 只能依据检索到的资料回答，不得使用自身知识补充学校政策。
2. 每个结论后标注来源，格式 `【来源N】`。
3. 检索结果与问题无关时，必须回答「知识库中暂无相关资料，建议咨询 XX 部门」，禁止猜测。

生成后解析 `【来源N】`，映射为引用卡片（文档名 + 片段 + 分数）写入 `message_sources`。

**越界引用处理**（DR-11）：若模型输出的编号超出本次实际提供的来源范围（例如只给了 5 条却写了 `【来源7】`），**直接剔除该标记**，不渲染卡片、不写入 `message_sources`，并在日志记 WARN。绝不因模型编造编号而伪造来源。

流式输出用 `st.write_stream`，流结束后再渲染引用区块与反馈按钮。

### 4.6 故障降级

在 `src/rag/chain.py` 捕获 LLM 异常（超时 / 401 / 欠费 / 网络中断）：

| 情况 | 行为 |
| --- | --- |
| 检索有结果 | 展示检索到的原文片段，提示「模型服务暂不可用，以下为原始资料」 |
| 检索无结果 | 提示「暂无相关资料」 |
| 未捕获异常 | 页面显示友好错误，不暴露堆栈；日志记录完整堆栈 |

### 4.7 异步入库与进度

- 上传后写 `documents` 记录（`status=active`）与 `ingest_tasks` 记录（`status=pending`）。
- 后台线程执行：解析 → 切片 → 按批（默认 32）向量化 → 按批更新 `done_chunks`。
- 前端轮询 `ingest_tasks` 刷新进度条；完成后提示可检索；失败展示 `error`。
- 大批量建库走 `scripts/ingest_cli.py`（同步执行，可见日志）。

**防重复提交**（DR-07）：Streamlit 每次交互都会重跑整个脚本，若不加保护，同一个文件可能被提交两次入库。

- 提交前在 `st.session_state` 中标记该文件已提交（键为 `doc_id` 或文件名 + 大小）；
- 服务端 `ingest_tasks` 写入前做幂等校验：同一 `doc_id` 若已存在 `pending/running` 任务，则拒绝重复创建。

**失败重试语义**（DR-05 裁决）：**复用原任务**，不新建记录。

- 重试时把该任务 `done_chunks` 归零、`error` 清空、`status` 重置为 `pending`，重新入队；
- 同一文件在列表中始终只有一行，不会出现多条任务记录；
- 重试前先清理该 `doc_id` 已写入的部分向量，避免残留脏数据导致重复命中。

### 4.8 认证、角色与数据隔离

- 密码：`hashlib.pbkdf2_hmac('sha256', pwd, salt, 200_000)`，存储格式 `算法$迭代$盐$哈希`；最少 6 位。
- 角色：`users.role` 为 `admin` / `user`；`users.status` 为 `active` / `disabled`。
- 登录态存 `st.session_state`；`app.py` 做守卫，无登录态一律跳登录页。
- **权限过滤（安全红线，FR-31）**：检索统一入口强制传 `user_id`，过滤条件固定为
  `is_public = 1 OR user_id = 当前用户`，可选叠加 `category`。
  公共文档在 Chroma 中 `user_id = -1`。
  **过滤条件为必传参数**：若上层未提供，`VectorStore.search()` 直接抛错，绝不降级为「无过滤」返回数据。

### 4.9 备份、恢复与数据删除

> **范围提示**：备份 / 恢复（FR-24）已由客户裁决**移出本期，归二期**。本节保留设计以备二期实现；一期的删除与注销能力**照常交付**。

| 操作 | 一期 | 流程 |
| --- | --- | --- |
| 备份 | 二期 | 导出 zip：`data/uploads/` 原始文件 + 元数据 JSON（users / documents / conversations / messages / feedback）+ `knowledge_base.yaml` 快照。**不含 `.env`**。向量不导出 |
| 恢复 | 二期 | 解压文件 → 重建 SQLite 记录 → 复用入库流水线重新向量化 |
| 删除文档 | ✅ 交付 | `documents.status=deleted` → `chroma.delete_by_doc_id` → 删除原始文件 |
| 用户注销 | ✅ 交付（Must） | 删除其全部 documents → `chroma.delete_by_user_id` → 删除 conversations / messages / feedback / ingest_tasks → 删除用户记录 |

所有向量删除统一走 `delete_by_doc_id` / `delete_by_user_id` 两个方法，禁止上层直接操作 Chroma。

**注销的回滚要求**：注销是跨库（SQLite + Chroma + 文件系统）操作，必须保证「要么全部完成，要么不留下半删状态」。实现顺序为：先删除向量与文件（可重入），再在单个 SQLite 事务中删除全部记录；若向量清理失败则中止并向用户报错，不进入 SQLite 事务。

## 5. 数据设计

### 5.1 SQLite 表结构

```sql
users (
  id INTEGER PK AUTOINCREMENT,
  username TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  display_name TEXT,
  role TEXT NOT NULL DEFAULT 'user',        -- admin / user
  status TEXT NOT NULL DEFAULT 'active',    -- active / disabled
  created_at TEXT NOT NULL
)

documents (
  id INTEGER PK AUTOINCREMENT,
  user_id INTEGER,                          -- NULL 表示公共文档
  is_public INTEGER NOT NULL DEFAULT 0,     -- 1=公共，0=个人
  filename TEXT NOT NULL,
  filetype TEXT,                            -- pdf / txt / md / image
  category TEXT DEFAULT 'uncategorized',    -- knowledge_base.yaml 的 key；个人资料未选则为 uncategorized
  size_bytes INTEGER DEFAULT 0,
  chunk_count INTEGER DEFAULT 0,
  status TEXT NOT NULL DEFAULT 'active',    -- active / deleted
  created_at TEXT, updated_at TEXT,
  FOREIGN KEY (user_id) REFERENCES users(id)
)

ingest_tasks (
  id INTEGER PK AUTOINCREMENT,
  doc_id INTEGER, user_id INTEGER,
  status TEXT NOT NULL DEFAULT 'pending',   -- pending/running/done/failed
  total_chunks INTEGER DEFAULT 0,
  done_chunks INTEGER DEFAULT 0,
  error TEXT,
  warning TEXT,                             -- 入库告警（如「疑似扫描件」），随任务落库并展示（CR-03 / v1.6）
  created_at TEXT, updated_at TEXT,
  FOREIGN KEY (doc_id) REFERENCES documents(id)
)

conversations (
  id INTEGER PK AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  title TEXT,
  created_at TEXT, updated_at TEXT
)

messages (
  id INTEGER PK AUTOINCREMENT,
  conversation_id INTEGER NOT NULL,
  role TEXT NOT NULL,                       -- user / assistant
  content TEXT NOT NULL,
  created_at TEXT
)

message_sources (                           -- 引用溯源
  id INTEGER PK AUTOINCREMENT,
  message_id INTEGER NOT NULL,
  doc_id INTEGER,
  filename TEXT,
  snippet TEXT,
  score REAL
)

feedback (
  id INTEGER PK AUTOINCREMENT,
  message_id INTEGER NOT NULL,
  user_id INTEGER NOT NULL,
  rating TEXT NOT NULL,                     -- useful / useless
  created_at TEXT NOT NULL
)

qa_metrics (                                -- 脱敏，不存 user_id
  id INTEGER PK AUTOINCREMENT,
  question_len INTEGER,
  answerable INTEGER,                       -- 1 有资料 / 0 拒答
  top_doc_id INTEGER,
  top_score REAL,
  latency_ms INTEGER,
  degraded INTEGER,                         -- 1 走了降级
  created_at TEXT NOT NULL
)
```

## 6. 数据流

### 6.1 文档入库流

```
上传 → 校验(类型/大小/文件名) → 落盘 data/uploads/<user_id>/
     → 写 documents(status=active) → 写 ingest_tasks(pending)
     → 后台线程(running)：解析 → 切片 → 分批向量化 → 分批更新 done_chunks
     → 结束(done / failed)
前端轮询 ingest_tasks 刷新进度
```

### 6.2 问答流

```
提问 → 取会话最近 N 轮历史 → Query 改写
     → 混合检索（权限过滤 + 可选分类过滤）
     → 命中？ 否 → 直接拒答（不调用 LLM）
              是 → 组装上下文 → LLM 流式生成
                    成功 → 流式输出 + 解析【来源N】→ 渲染引用卡片
                    失败 → 降级：展示检索片段
     → 落库 messages / message_sources / qa_metrics → 展示反馈按钮
```

### 6.3 删除 / 注销流

```
删文档：documents.status=deleted → chroma.delete_by_doc_id → 删原始文件
注销  ：删用户 documents → chroma.delete_by_user_id
      → 删 conversations/messages/feedback/ingest_tasks → 删 users 记录
清理  ：90 天前的 qa_metrics 定时删除
```

## 11. 异常处理策略表

| 场景 | 触发条件 | 系统行为 | 用户可见反馈 | 日志 |
| --- | --- | --- | --- | --- |
| 文件类型不支持 | 后缀不在白名单 | 跳过该文件，继续处理同批其他文件 | 「不支持的文件类型：xxx」 | WARN |
| 文件超限 | 单文件 > 20MB | 同上 | 「文件超过 20MB 上限」 | WARN |
| 文件为空 | 提取文本为空或全空白 | 任务置 `failed` | 「未能从文件中提取到文本」 | WARN |
| 图片型 PDF | 平均每页字符数 < 20 | 按可提取文本入库，并把告警写入 `ingest_tasks.warning` | 「该文件疑似扫描件，建议后续启用 OCR」（文档列表行内展示） | WARN |
| PDF/DOCX 解析异常 | 解析器抛错 | 任务置 `failed`，写 `error` | 显示失败原因 + 「重试」按钮 | ERROR（含堆栈） |
| 加密 PDF | `is_encrypted=True` | 尝试空密码解密，失败则置 `failed` | 「文件已加密，无法解析」 | WARN |
| 向量化失败 | Embedding 调用/加载异常 | 任务置 `failed`，已写入的批次保留 | 显示失败原因 + 「重试」按钮 | ERROR |
| 入库进程中断 | 启动时发现残留 `running` 任务 | 统一置为 `failed` | 列表中显示可重试 | WARN |
| LLM 超时 / 401 / 欠费 | 调用异常 | **降级**：展示检索到的原文片段 | 「模型服务暂不可用，以下为原始资料」 | ERROR（含状态码） |
| LLM 异常且无检索结果 | 同上且检索为空 | 输出拒答文案 | 固定拒答文案 | ERROR |
| 检索无结果 | 命中为空或全低于阈值 | 不调用 LLM | 固定拒答文案 | INFO |
| 检索服务异常 | Chroma 读取失败 | 中止本次问答，不影响其他功能 | 「检索服务暂时不可用，请稍后重试」 | ERROR |
| 数据库写锁 | SQLite `database is locked` | 短事务重试 3 次（间隔递增，由 `db.py` 的 `retry_on_write_lock` 实现，与 `busy_timeout` 两层保护） | 通常无感；持续失败则提示稍后重试 | WARN |
| 未登录访问 | 无登录态 | 渲染登录页 | 登录页 | INFO |
| 越权访问管理员页 | `role != admin` | 拦截并跳转问答页 | 「无权访问该页面」 | WARN |
| 跨用户检索越权 | 检索过滤条件缺失 | 视为代码缺陷，直接抛错不返回数据 | 「系统异常」 | ERROR（必须修复） |
| 并发写同一文档 | 重复提交同一文件 | 允许，产生两条独立记录 | 无 | INFO |
| 备份文件损坏 | 解压或 JSON 解析失败 | 中止恢复，不改动现有数据 | 「备份文件损坏，未做任何修改」 | ERROR |
| 配置文件缺失/格式错 | yaml 解析失败或缺 key | 启动失败并给出示例 | 启动日志明确报错 | ERROR |
| API Key 未配置 | `LLM_API_KEY` 为空 | 启动时校验，问答时降级 | 启动提示 + 问答走降级 | ERROR |

**统一原则**

1. 单个文件失败不拖垮整批上传。
2. 检索链路不依赖 LLM，LLM 挂了系统仍可用。
3. 不向用户暴露堆栈，完整堆栈只进日志。
4. 任何「不返回数据」的情况都必须有明确文案，不允许静默失败。

## 12. 已知风险与技术债

| 项 | 说明 | 处理 |
| --- | --- | --- |
| 本地 BGE 在 M1 CPU 上并发编码受限 | 20 人并发时可能排队 | 一期接受；必要时切云端 Embedding 或加缓存 |
| Chroma 元数据过滤语法随版本变动 | `$and` / `$or` 组合需按实际版本验证 | 检索封装统一，便于单点适配 |
| 异步入库用后台线程而非任务队列 | 进程重启会丢失运行中的任务 | 一期接受；启动时将 `running` 任务标记为 `failed` 供重试 |
| 图片型资料无法入库 | 依赖 OCR | 已列为高风险可提前项 |
| Streamlit 版本升级可能破坏自定义 CSS | 主题样式范围窄 | 出问题可一键回退默认主题 |
| 额度无保护 | 客户明确接受 | 保留管理员禁用账号能力 |
