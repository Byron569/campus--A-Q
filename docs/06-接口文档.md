## 0. 口径说明（重要）

**本项目不提供 REST API。** 前端是 Streamlit，服务端渲染，前后端不分离，不存在 HTTP 接口层。

因此本文档中的「接口」指两类真实存在的契约：

| 类别 | 说明 | 谁会依赖 |
| --- | --- | --- |
| **A. 模块间函数接口** | 项目内部各模块之间的调用契约（Python 函数签名） | 开发、测试、后续二期扩展 |
| **B. 外部服务接口** | 项目对外调用的第三方 API（大模型与向量化） | 配置、运维、成本核算 |

系统架构与数据库表设计已在 `docs/02-架构设计.md` 第 1、5、6、7 章给出，本文档不重复，只补函数级契约。

## 2. 外部服务接口

### 2.1 大模型（Chat Completions）

| 项 | 内容 |
| --- | --- |
| 协议 | HTTPS，OpenAI 兼容 `POST {base_url}/chat/completions` |
| 调用方 | `src/rag/chain.py`（生成答案）、`src/rag/rewrite.py`（Query 改写） |
| 认证 | `Authorization: Bearer <LLM_API_KEY>` |
| 流式 | 生成答案使用 `stream=true`；改写使用非流式 |
| 温度 | `LLM_TEMPERATURE`，默认 0.2 |
| 超时 | 60 秒；`max_retries=1` |
| 失败行为 | 抛异常 → 上层走**降级**（展示检索原文片段，FR-21） |

**供应商地址**

| provider | base_url | 默认模型 |
| --- | --- | --- |
| deepseek（默认） | `https://api.deepseek.com/v1` | deepseek-chat |
| dashscope | `https://dashscope.aliyuncs.com/compatible-mode/v1` | qwen-max |
| zhipu | `https://open.bigmodel.cn/api/paas/v4` | glm-4-plus |
| openai | `https://api.openai.com/v1` | gpt-4o |
| custom | `LLM_BASE_URL` | `LLM_MODEL` |

### 2.2 向量化（Embeddings）

| 模式 | 调用方式 | 认证 | 说明 |
| --- | --- | --- | --- |
| `local`（默认） | 进程内调用 `sentence-transformers`，无网络请求 | — | 模型 `BAAI/bge-small-zh-v1.5`，向量不出本机 |
| `cloud` | HTTPS，OpenAI 兼容 `POST {base_url}/embeddings` | `Authorization: Bearer <EMBEDDING_API_KEY>` | 地址由 `EMBEDDING_BASE_URL` 指定 |

## 3. 数据结构定义

### 3.1 核心返回结构

| 结构 | 字段 | 说明 |
| --- | --- | --- |
| `LoadResult` | `sections: list[RawSection]`、`needs_ocr: bool`、`warning: str` | 文档解析结果 |
| `RawSection` | `text: str`、`page: int | None` | 原始段落及页码 |
| `Chunk` | `text: str`、`chunk_index: int` | 切片 |
| `IngestResult` | `doc_id`、`chunk_count`、`needs_ocr`、`warning`、`elapsed_ms` | 入库结果 |
| `SearchHit` | `text`、`score: float \| None`、`filename`、`doc_id`、`chunk_index`、`category`、`matched_by: str` | 检索命中；`score` 为**余弦相似度（仅向量路可得，越大越相关）**；`matched_by` 取值 `vector` / `bm25` / `both`（DR-15） |
| `AnswerResult` | `text`、`sources: list[SearchHit]`、`refused: bool`、`degraded: bool`、`latency_ms` | 问答结果 |

### 3.2 Chroma 元数据结构

```json
{
  "doc_id": 12,
  "user_id": 3,
  "is_public": 0,
  "category": "freshman",
  "filename": "学生手册.pdf",
  "chunk_index": 8,
  "source_type": "text"
}
```

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| `doc_id` | int | 关联 `documents.id` |
| `user_id` | int | 个人资料为本人 id；**公共文档固定为 `-1`** |
| `is_public` | int | `1`=公共，`0`=个人（整数而非布尔，避免过滤兼容问题） |
| `category` | str | 分类 key；未选为 `uncategorized` |
| `chunk_index` | int | 切片序号 |
| `source_type` | str | `text`（一期）；二期 OCR 为 `ocr` |

## 4. 异常约定

### 4.1 自定义异常

| 异常 | 触发场景 | 上层处理 |
| --- | --- | --- |
| `ConfigError` | 配置文件缺失或格式错误 | 启动即失败，日志给出示例 |
| `ProviderError` | 供应商未配置、Key 缺失、provider 未知 | 启动提示；运行期走降级 |
| `UnsupportedFileType` | 上传后缀不在白名单 | 单文件报错，不影响同批 |
| `ParseError` | 文件损坏、加密、解析器异常 | 任务置 `failed`，提供重试 |
| `IngestError` | 向量化失败等入库期错误 | 同上 |
| `PermissionFilterError` | 检索未传 `user_id` | **直接抛错，不返回数据**（安全红线） |
| `AccountDisabled` | 被禁用账号尝试登录 | 提示「账号已被禁用」 |
| `LLMUnavailable` | 模型调用超时 / 401 / 欠费 | 降级展示检索原文 |

### 4.2 统一原则

1. 单个文件失败不拖垮整批。
2. 检索链路不依赖 LLM，模型故障时系统仍可用。
3. 不向用户暴露堆栈，完整堆栈只进日志。
4. 任何「不返回数据」的情况都必须有明确文案，不允许静默失败。
